# Flight Price Predictor - AI & Architecture Details

This document provides a detailed technical breakdown of the artificial intelligence, machine learning models, parameters, and APIs used in the Flight Price Predictor application.

---

## 1. The Machine Learning Brain (`model.pkl`)

A `.pkl` (pronounced "pickle") file is a standard format used in Python to save or "serialize" data and objects. In this application, `model.pkl` acts as the literal "brain" of the AI.

### Why is it used?
When you run the `train_model.py` script, the computer analyzes thousands of rows of historical flight data to find mathematical patterns and "learns" how to predict flight prices. This training process takes time and computing power. 

Instead of forcing the application to re-learn everything from scratch every single time a user clicks "Predict Price", Python takes that fully trained, smart AI model and saves it into the `model.pkl` file.

### What is inside the file?
It contains the saved state of your machine learning algorithms, specifically:
*   **The Random Forest Regressor:** The hundreds of decision trees the AI built during training.
*   **Data Transformers:** The logic that converts categorical data (like cities and airlines) into numbers.
*   **Metrics & Metadata:** Information like the R² score, MSE, and sample size.

### How the app uses it:
When the backend server (`app.py`) starts, `utils/predict.py` uses the `joblib` library to load this saved "brain" into RAM. When a user asks for a price prediction, the app simply hands the flight details to the loaded model, which outputs the price instantly.

## 2. Prediction Parameters Explained

The results panel in the UI displays several metrics dynamically generated by the backend (`utils/predict.py` and `train_model.py`):

*   **Forecasted Liquidity (Predicted Price):** The final estimated price of the flight ticket. The base price is predicted by the Random Forest model, and then business multipliers (cabin class, festival periods, membership status) are applied.
*   **Recommendation Text:** Dynamically generated advice (e.g., "Good time to book!") based on whether the predicted price is below a calculated average threshold or if the flight is less than 5 days away.
*   **ACCURACY (Confidence):** Represents the model's confidence in its specific price prediction. Calculated by looking at the standard deviation (variance) across all individual decision trees inside the Random Forest. High agreement equals high confidence.
*   **TREND:** A label categorizing the price into "Low", "Medium", or "High" buckets based on calculated thresholds.
*   **R² (R-Squared):** The coefficient of determination, measuring how well the machine learning model fits the historical data (e.g., an R² of 0.94 means it explains 94% of the variance).
*   **MSE (Mean Squared Error):** A statistical measure of the average squared difference between estimated and actual values. Simulated during inference to show a real-time error margin.
*   **Volatility:** The expected price fluctuation margin, calculated as the standard deviation of predictions across all trees in the Random Forest.
*   **Sample:** The number of historical flight data records used to train the model.
*   **Method:** The specific algorithm used (Random Forest Regressor).
*   **F1-Approx:** A holistic "health score" approximated for the UI context (since standard F1 is for classification, not regression).
*   **Hidden Intelligence Active:** A UI indicator confirming that custom backend multipliers (like Departure Window or Membership status) were factored into the final price.

## 3. Python Libraries Used

The backend relies on the following key external libraries:

### Data Science & Machine Learning
*   **`pandas`**: Used to load, clean, and manipulate the flight datasets.
*   **`numpy`**: Used for core mathematical calculations and array operations.
*   **`scikit-learn`**: The main machine learning library used to train the `RandomForestRegressor` and handle data encoding.
*   **`joblib`**: Used to efficiently save and load the trained `model.pkl` file.

### Web & API Framework
*   **`fastapi`**: The high-performance core framework used to build backend routes (`/predict`, `/chat`).
*   **`uvicorn`**: The ASGI web server used to run the FastAPI application.
*   **`pydantic`**: Used by FastAPI to validate incoming request data (e.g., `FlightQuery`).

## 4. Chatbot Architecture: The Two-Way System

The conversational AI feature in `chatbot/rule_bot.py` utilizes a smart, hybrid "two-way" routing system depending on what the user asks:

### Route A: Flight-Related Queries (Local Machine Learning)
If the user asks something like *"Predict flight from Delhi to Mumbai tomorrow"*:
1.  **Intent Detection:** The bot uses Regex (Regular Expressions) to detect flight keywords and extract the source, destination, and dates.
2.  **Local Prediction (0 Cost):** It bypasses external APIs entirely. It formats the data and feeds it directly into your local `model.pkl` to calculate the price.
3.  **Speed:** Because it runs entirely on your local machine learning model, the response is nearly instantaneous.

### Route B: General Questions (Pollinations.ai API)
If the user asks a conversational question like *"What is your name?"* or general travel advice, the bot switches to its external AI mode:

#### What is Pollinations.ai?
For general questions, the chatbot sends the user's message to `text.pollinations.ai`. 
*   **Open Source & Free:** Pollinations.ai is an open-source platform that provides free proxy access to powerful LLMs (like OpenAI's models) without requiring developers to set up API keys or manage billing.
*   **How it works:** It acts as a wrapper. Your app sends an HTTP request to their URL, and they route the prompt to the backend model and return the generated text.

### Response Time & Latency
Because Pollinations.ai is a shared, free resource, response times typically range from 3 to 6 seconds. This delay is due to:
1.  **Shared Server Load:** Thousands of requests are processed simultaneously in a queue.
2.  **Generation Compute:** Large Language Models generate text one token (word) at a time, which inherently takes GPU processing time.
3.  **Proxy Hops:** Network latency is introduced as the request bounces from your local app to Pollinations, then to the LLM provider, and back again.

#### How to Improve Speed
If you want the chatbot to feel instantaneous for general queries, consider these architectural upgrades:
*   **Switch to Groq API (Recommended):** Groq uses specialized hardware (LPUs) to run open-source models at blazing speeds (often under 0.5 seconds). They have a generous free tier and could replace the Pollinations endpoint.
*   **Implement Streaming:** Modify the backend and frontend to stream the response token-by-token (like ChatGPT). While total generation time is the same, the user sees text immediately, making it *feel* instant.
*   **Expand Local Logic:** Add more hardcoded responses to `fallback_general_qa()` in `rule_bot.py` for common questions to bypass external APIs completely.
